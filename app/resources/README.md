# Harmony remotes: зоны кнопок и раскладки экранов

Данные делятся на три слоя.

1. **Железо** (`remotes/<id>/zones.json`): физические кнопки в пикселях фото. От режима не зависит.
2. **Профиль** (`remotes/<id>/profile.json`): фото, размер, рамка экрана, какая раскладка используется в каком режиме.
3. **Раскладки экрана** (`layouts.json`): где на экране лежат ячейки. Общая библиотека для всех пультов.

```
layouts.json
remotes/
  900/ one/ 600/ 650/ 665/ 700/ 1000/ 1100/ 1100i/
     profile.json   zones.json   photo.png
```

## Пульты

900, One, 600, 650, 665, 700, 1000, 1100 и 1100i. У 1100 и 1100i два разных фото (исходные `photo_fcc753.png` у 1100 и `photo_7af6da.png` у 1100i, в архиве оба названы `photo.png`), зоны у них свои, а раскладки и экраны общие (по описанию из обзоров 1100i отличается от 1100 только комплектацией без RF-модуля, внешний вид экрана одинаковый; это не подтверждено сравнением экранов).

## Фото

- Во всех папках фото называется `photo.png`, в `profile.json` везде `"image": "photo.png"`.
- Фото обрезаны вплотную по границам пульта и масштабированы без искажения: **длинные пульты имеют высоту ровно 1500 px, широкие ширину ровно 680 px**.
- Холст у длинных 450×1500 (самый широкий пульт 402 px, холст округлён вверх до кратного 50), у широких 680×550 (самый высокий 504 px). Пульт стоит по центру, остальное прозрачное.
- Пропорции оригиналов сохранены. Для 900 они совпадают с габаритами 222×58 мм из справочника. Для остальных моделей реальные габариты я не проверял.
- Все координаты (`zones.json`, `screen`) пересчитаны под эти фото.

## profile.json

| Поле | Значение |
|---|---|
| `id`, `name` | идентификатор и название модели |
| `image` | имя файла фото в той же папке |
| `size` | `[ширина, высота]` фото (холст) в пикселях |
| `screen` | `[x, y, w, h]` светящейся части дисплея, в пикселях фото |
| `touch` | `true`, если экран принимает касания |
| `modes` | «режим → id раскладки из layouts.json» |

Режимы: `activities`, `command`, `favorites`, `transport`, `keypad`. В список входят экраны, на которых можно переназначать кнопки, и экран выбора активности. Списки Devices и Options, Settings и подобные не размечаются. Режима нет в `modes`, значит раскладки для него нет: подсвечивай `screen` целиком.

## zones.json

Массив зон `{id, rect:[x,y,w,h], radius, kind}` в пикселях фото.

- `radius > 0`: радиус скругления в пикселях. `radius < 0`: доля от стороны (`-0.5` круг, `-0.4` почти круг). Это моя трактовка по исходным файлам, подтверди.
- `kind` физических зон: `Key`, `System`, `PagePrev`, `PageNext`, `ScreenSoft`, `ScreenActs`.
- Имена кнопок одинаковы у всех пультов (`Play`, `VolumeUp`, `Number5`...).
- Имена, которых не было в 900, придуманы мной: `WatchTV`, `WatchMovie`, `ListenMusic`, `MoreActivities` (верхние кнопки 600-серии), `SoftLeft1..4`, `SoftRight1..4` (физические кнопки у экрана).

## layouts.json

Массив раскладок `{id, description, ref:[w,h], touch, zones:[...]}`.

- `ref` это система координат экрана. Положение на фото: `x_фото = screen.x + zone.x * screen.w / ref.w`, `y_фото = screen.y + zone.y * screen.h / ref.h`. Раскладки от масштаба фото не зависят.
- `ref`: 232×290 у 900/One, 172×182 у 600-серии, 320×240 у 1000/1100/1100i.
- `kind` зон экрана: `ScreenSlot` (плитка), `ScreenKey` (кнопка на экране), `ScreenSide` (ячейка боковой панели или подпись над физической кнопкой), `ScreenLabel` (некликабельная подпись).
- `button`: id физической кнопки из `zones.json`, соответствующей ячейке. Нет поля: ячейка сенсорная.
- `centerLastRow: true`: неполный последний ряд плиток центрируется.
- `style`: палитра экрана. `t1000` (синий глянец, светлые плитки, серебристые кнопки), `t1100` (тёмно-бирюзовый фон, чёрные плитки и панели), `h600` (600/650/665/700, отдельный отрисовщик). Нет поля: вид 900. Цвета сняты с фото экранов пультов.
- `tile`: вид плиток на местах `ScreenSlot` (поэтому работает и `centerLastRow`). `"image": "sprites/tile_1100.png"` растягивается на каждую ячейку, `"shadow": true` добавляет мягкую тень вправо-вниз (как у плиток 1000), `"text"` — цвет подписи. Запасной вид, если картинки нет: ровная заливка `{"color": "#AARRGGBB", "border": "#RRGGBB"}`. Так сделано и избранное 1100 и 1000: это уменьшенные плитки активностей. У 1000 сетка взята как у 1100.
- Что делает кнопка экрана (`ScreenKey`, `ScreenSide`), задаётся одним полем:
  - `"key": "<id>"` — назначаемая кнопка. id — имя кнопки в конфигурации (`Play`, `Number5`, `Menu`, `UpArrow`...), как у физических кнопок в `zones.json`. Такие кнопки попадают в список назначаемых кнопок модели. У `ScreenSide` с `"button"` та же кнопка срабатывает и от физической кнопки у экрана.
  - `"goto": "<режим>"` — открывает другой экран (углы, Home). Если режима нет в `modes` профиля, кнопка остаётся картинкой.
  - `"page": -1 | 1` — листает страницу экрана.
  - `"system": true` — системная кнопка без команды (Help, Settings).
  - Нет поля — кнопка только рисуется.
- `compose: true`: экран собирается из картинок `resources/sprites` по `remotes/<id>/screens.json` Так сделаны все экраны 1000, 1100 и 1100i (у 1100i копия `screens.json` 1100).
  - `screens.json`: `images` (имя → `{"file": "sprites/..."}`) и `screens` (режим → список картинок `{"image", "rect"}` в единицах `ref`, рисуются по порядку, поздние поверх ранних). `"tint": "#rrggbb"` перекрашивает картинку: так значок текущего экрана в углу становится зелёным у 1000 (`#8BAD2D`) и оранжевым у 1100 (`#FAA72C`). Необязательные `label`, `labelColor`, `labelAlign`, `layer`.
  - Плитки, подписи панелей (`key` у `ScreenSide`), часы, «1 of 3», `Caption` и подсветку программа рисует по раскладке поверх картинок. `PageWord` — переведённая надпись «Page» на стрелке листания 1000.
  - У `tile` можно задать цвет подписи `"text": "#rrggbb"` (у светлых плиток 1000 тёмный, без тени).
  - Заголовок `Heading` на собранном экране рисуется с переводом.
- `ScreenPanel`: некликабельная подложка, рисуется под остальными зонами. `role`: `band` (чёрная кромка/полоса, `rect` может выходить за экран), `oval` (кольцо вокруг транспорта), `side` (боковая панель; разделители ставятся между ячейками `ScreenSide`, а кнопки `ScreenKey` внутри панели рисуются без подложки).
- `quality`: `low` или `medium` у раскладок, снятых с плохих картинок.

| Раскладка | Пульты | Режим |
|---|---|---|
| `list_3` | 900, One | activities |
| `grid_2x3` | 900, One | command |
| `soft_2x2` | 600, 650, 665, 700 | command |
| `t1000_activities`, `t1000_transport` | 1000 | activities, transport |
| `t1100_activities`, `t1100_command`, `t1100_transport`, `t1100_keypad` | 1100, 1100i | activities, command и favorites, transport, keypad |

Содержимое экранных ячеек программа собирает сама, без отдельной таблицы: подписи и плитки берутся из конфигурации (активности, экранные кнопки), значки кнопок уже есть на картинках экрана, цифры и подписи служебных кнопок заданы в `RemoteView`.

## Что проверено и что нет

- Координаты сняты по картинкам на глаз и сверены с экраном в программе. Погрешность несколько пикселей, у тонких кнопок (боковые полоски 1100, цветные клавиши) больше.
- `t1100_command` снят с экрана избранных каналов Watch TV. Для других активностей меняется содержимое панелей, а не позиции.
- `t1100_transport` (картинка 259×194) самый грубый, `quality: low`. `t1100_keypad` пересчитан с кадра вместе с корпусом, `quality: medium`.
- Позиции плиток зависят от темы оформления (на немецком снимке 1100 интервалы другие). Здесь везде стандартная тема.
- У 1000 нет раскладок для `command` и `keypad` (нет картинок), раскладки 1100 не подходят: у 1000 нет физических боковых кнопок.
- `grid_2x3` помечен `unverified`: экран `command` у 900/One не видел ни на одном снимке.
- У 600-серии (600, 650, 665, 700) один режим `command`: у всех четырёх одинаково. Списки активностей и устройств на их экране в руководстве описаны, но кнопки на них не переназначаются и снимков нет, поэтому не размечены.
- Режимы `settings`, `game`, `custom` (звезда) у 1000/1100 не размечены: подсвечивай `screen` целиком.
- Связь 600-серии: `Screen1` ↔ `SoftLeft1`, `Screen2` ↔ `SoftRight1`, `Screen3` ↔ `SoftLeft2`, `Screen4` ↔ `SoftRight2`.

## Правки без пересборки

Рабочая папка — `resources` рядом с исполняемым файлом. При запуске программа
создаёт её и восстанавливает отсутствующие штатные файлы из встроенной копии.
Существующие файлы не перезаписываются, включая изменённые и повреждённые.
Настройка выбора папки больше не используется. Если раньше использовалась другая
папка, перенесите свои правки в `resources` вручную.

**Пульт → Открыть папку ресурсов пультов** открывает её в проводнике.
Загрузка идёт из этой папки: `remotes/<id>/photo.png`, `profile.json`, `zones.json`,
`screens.json`, общие `layouts.json` и `sprites/`. Новые файлы штатных ресурсов
после обновления программы добавляются, существующие остаются без изменений.
Если каталог установки недоступен для записи и нужных файлов нет, программа
показывает ошибку с путём; скрытая запасная рабочая папка не создаётся.

Программа следит за файлами (`QFileSystemWatcher`) и перечитывает ресурсы после
сохранения; ошибка показывается в строке состояния и журнале. Вручную —
**Пульт → Обновить ресурсы пультов** или снова открыть выбор модели.
Перед перечитыванием недостающие штатные файлы также восстанавливаются.
Пока идёт обмен с пультом, автоперечитывание откладывается.
Для возврата одного штатного файла к исходному удалите его и обновите ресурсы.
Пользовательские модели, отсутствующие во встроенной копии, не восстанавливаются.

**Пульт → Выгрузить ресурсы пультов…** дополнительно позволяет выгрузить текущий
снимок с описанием структуры `HARMONY-RESOURCES.md`; замена существующих файлов
при этой явной операции требует подтверждения.

Обновляется единый снимок: фото, зоны, экранные раскладки, спрайты и списки кнопок.
Ошибка JSON, некорректная зона или несовпадение размеров фото и профиля отменяет
всё обновление с указанием файла. До исправления используется предыдущий корректный
снимок (при первом запуске — встроенные ресурсы). Последний внешний снимок хранится
только в памяти. Редактирование ресурсов не изменяет сохранённые назначения команд.
Редактор зон показывает и папки `remotes/<id>/` с `profile.json`, которые загрузчик
отклонил: их можно открыть и исправить разметку. Поля `id` и `name` в profile.json
правятся в текстовом редакторе — `id` обязан совпадать с именем папки.

Если файл изменили в редакторе зон и одновременно в текстовом редакторе, сохранение
предлагает **Сохранить мои правки поверх**: правки редактора записываются в текущий
файл, а остальные изменения в нём остаются (заменяются только те места, которые правил
редактор). Второй вариант — **Загрузить заново, отбросив мои правки**.

### Добавление модели

Создайте `remotes/<id>/` с `profile.json`, `photo.png`, `zones.json` (и при
необходимости `screens.json`). Можно скопировать папку похожей модели.
В `profile.json` измените `id` и `name`; id должен совпадать с именем папки,
содержать строчные латинские буквы, цифры, `_` или `-` и начинаться с буквы/цифры.
После обновления ресурсов новая модель появится в выборе пульта. Её id сохраняется
в проекте. Для открытия с разметкой на другом компьютере перенесите также её папку.
Удаление папки не меняет модель проекта: исчезают разметка и доступ к записи.

Поля подключения:

| Поле | Значения |
|---|---|
| `driver` | `none` — без подключения; `hid` — имеющееся чтение резервной копии по HID; `harmony900` — реализованный сетевой протокол 900 |
| `configFormat` | `unsupported` — формат устройства не реализован; `harmony900` — существующий формат конфигурации 900 |

Для новой модели без этих полей используются `none` и `unsupported`. Старые внешние
профили штатных моделей наследуют значения встроенного профиля. Неизвестное значение
отклоняет обновление. `writable` из JSON не используется: запись определяется
сочетанием реализованных драйвера и формата. В текущей реализации это только
`harmony900` + `harmony900`; проверка архитектуры и skin исходного файла сохраняется.
`hid` не добавляет поддержку новых USB-идентификаторов и не умеет записывать
конфигурацию. Совпадение внешнего вида не доказывает совместимость протоколов.

Пример профиля на основе 600:

```json
{
  "id": "custom-600",
  "name": "Мой пульт",
  "image": "photo.png",
  "size": [450, 1500],
  "screen": null,
  "modes": {},
  "driver": "hid",
  "configFormat": "unsupported"
}
```

Размер должен совпадать с вашим PNG. Область экрана и раскладки можно скопировать из
совместимого визуального профиля. Будущий редактор может сохранять эти же файлы и
вызывать `remoteResources::reload()`.
