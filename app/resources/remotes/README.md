# Описания пультов

Каждая папка названа стабильным идентификатором модели и содержит:

- `photo.png` — фото с прозрачным фоном.
- `profile.json` — `id`, `name`, имя файла `image`, исходные размеры `size: [width, height]`,
  область экрана `screen: [x, y, width, height]` либо `null`, если экран пока не размечен.
- `zones.json` — массив зон; `[]` означает отсутствие интерактивных кнопок.

Координаты задаются в пикселях исходного фото, от его левого верхнего угла.
Фото, экран, подсветка и области кликов масштабируются вместе с сохранением пропорций.
Для горизонтальных 1000/1100/1100i используется размер 680×500, для вертикальных — 400×1500.
Размер `size` должен совпадать с PNG: при несовпадении интерактивная разметка отключается.

Пример зоны:

```json
{ "id": "VolumeUp", "rect": [50, 714, 70, 74], "radius": 14, "kind": "Key" }
```

`rect` содержит x, y, ширину, высоту (не координаты правого нижнего угла).
Положительный `radius` — радиус углов в пикселях; отрицательный — доля короткой стороны.
`kind`: `Key`, `System`, `ScreenActs`, `ScreenSoft`, `PagePrev`, `PageNext`.
Идентификаторы `Key` соответствуют именам командных кнопок конфигурации.
Список кнопок для ручного назначения берётся только из корректных зон `Key` выбранной
модели. Если таких зон нет, редактирование кнопок (включая вставку) отключено.
Если зоны есть, можно назначать команды и сохранять проект; это не включает запись
на экспериментальный пульт. Уникальные кнопки могут иметь собственные идентификаторы.
Существующие назначения при смене модели автоматически не преобразуются.

У 900 перенесены все 48 зон. Фото расширено с 396 до 400 пикселей справа:
координаты исходной разметки не сдвигаются. Отрисовщик содержимого LCD пока общий,
с макетом Harmony 900; для других экранов потребуется отдельный макет.
Исключение — раскладки со `"style": "h600"` в `layouts.json` (600/650/665/700): их рисует
`paintCompactScreen` по виду настоящего экрана. Основной цвет фона задаётся в `profile.json`
полем `screenTint` (`"#rrggbb"`): серый у монохромного 600, розовый у цветных моделей
(цвета подобраны без фото экрана, их стоит сверить).
Экраны 1000/1100/1100i собираются из картинок `../sprites` по `screens.json` модели
(раскладки с `"compose": true`, см. `../README.md`). Если картинки не загрузились,
остаётся запасной вид с палитрой `style` и подложками `ScreenPanel`.

CMake генерирует общий каталог моделей из `profile.json` и встраивает ресурсы в exe.
Для штатных ресурсов после изменения JSON/PNG нужна пересборка. Для правок без пересборки
редактируйте файлы в папке `resources` рядом с программой (см. ../README.md).
Добавленная модель в штатном каталоге подхватывается при сборке автоматически. Протоколы подключения остаются в `transport`, форматы — в `core`.
Поля `driver` и `configFormat` выбирают реализованные адаптеры; допустимые значения
и добавление внешних моделей описаны в `../README.md`.
