# Пульты с USB HID: One, 600, 650, 665, 700

Состояние на 15.11.2026. Таблица всех моделей — [models.md](models.md).

## Что есть

- **Чтение исходной конфигурации в `*.hid.json`** прямо из программы: выбрать модель в шапке,
  подключить один пульт по USB, закрыть другие приложения Logitech, нажать «Прочитать с пульта»
  и выбрать, куда сохранить файл. Если отменить окно сохранения, автоматическая копия остаётся
  в папке резервных копий. Открытая конфигурация редактора не меняется, на пульт ничего не пишется.
- **Перенос готовых файлов** через встроенную libconcord: «Пульт → Файлы конфигурации — все модели…»
  читает EZHex и записывает совместимый готовый EZHex с резервной копией. Для One проверяются
  skin/protocol, карта flash, сигнатуры GSPM/LWJL/PTYY, указатель конца и XOR16.
- **Разбор GSPM (One) в ядре**, только чтение: `core/src/formats/gspm*.cpp` — внешняя структура,
  мастер-индекс, индекс «устройство → команды», экраны и шрифты. Проверен на синтетических
  образах; в программу и CLI пока не подключён.

На физических One и 665 из Harmony ничего не проверялось. Тесты с имитацией HID этого не заменяют.

## Чего нет

Редактора конфигураций One и 600-серии. Программа проверяет фактические architecture и skin
пульта, а не выбор в меню, и запись экспериментального проекта блокирует в интерфейсе и в ядре.

Для полного цикла One нужно:

1. Настоящий дамп One — для проверки адресов и сохранения без правок байт в байт. Его пока нет.
2. Адаптер GSPM: устройства, команды, назначения и активности в модель редактора и обратно,
   с сохранением неизвестных разделов исходного образа (по образцу генераторов afterglow и re-harmony).
3. Хранение исходного образа в документе и отмена правок (см. [core-refactoring-plan.md](core-refactoring-plan.md)).
4. Проверки на реальной конфигурации: сохранение без правок, смена назначения, новое устройство,
   правка активности, повторное открытие.

Для 600–700 (architecture 14) готового генератора нет ни в одном из исследованных проектов —
сначала нужен реальный дамп ([read-665.md](read-665.md) — инструкция для владельца пульта).

## Формат `*.hid.json`

JSON версии 1 (`format=harmony-hid-backup`): исходный ответ GET_VERSION в hex,
firmware/board/flash/architecture/skin, время UTC, начальный адрес, размер, SHA-256 и
неизменённые байты конфигурации в Base64. Это контейнер для исследования, а не EZHex и не
файл для записи. SHA-256 проверяет передачу файла, а не заменяет контроль протокола.
Файл создаётся только после полного чтения; при ошибке можно прислать текст из журнала.

## Протокол чтения

`HarmonyHidReader` (`transport/src/harmonyHidReader.cpp`) реализует classic HID сам;
статически подключённая HIDAPI 0.14.0 даёт только системный доступ к USB. На Windows —
системный HID-драйвер (заменять его через Zadig не нужно), на macOS — IOKit, на Linux — hidraw
(для сборки нужен `libudev-dev`). Права на `/dev/hidraw*` даёт правило
`packaging/linux/usbnet/70-harmony-hid.rules` (046d:c110–c14f, тег `uaccess`); его ставит
«Настроить связь по USB…» вместе с настройкой 900.

- Команды: GET_VERSION (0x10) и READ_FLASH (0x55). Для PID c121 сначала RESET_USB (0xe1, 0x01) —
  инициализация обмена, а не сброс устройства и не запись.
- **Architecture 14** (600–700): база 0x030000, cookie 0x4D505347, трёхбайтный указатель конца
  со смещения 4; разрешены skin 66/69/71–75.
- **Architecture 12 / skin 54** (One): база 0x040000. Пары architecture/skin проверяются вместе:
  skin One на architecture 14 отклоняется.
- Блок не больше 1022 байт (700 для protocol 0); проверяются номера пакетов, длины, DONE,
  ёмкость flash и стабильность заголовка. Неизвестная архитектура или микросхема — отказ.

Источник описания протокола — [Concordance](https://github.com/jaymzh/concordance)
(GPL-3.0-or-later; `libconcord/remote.cpp`, `remote_info.h`, `protocol.h`), авторы
Kevin Timmerman и Phil Dibowitz. Описание GSPM — afterglow и re-harmony, см. [research.md](research.md).
