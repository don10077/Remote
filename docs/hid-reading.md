# Экспериментальное чтение Harmony One/600/650/665/700

Всё выполняется из Harmony: выбрать модель в шапке, подключить один пульт по
USB, закрыть другие приложения Logitech, нажать «Прочитать с пульта».
После чтения выбрать, куда сохранить файл `*.hid.json`, и прислать этот файл.
Отмена окна экспорта оставляет автоматическую копию в папке резервных копий.
Открытая конфигурация редактора при этом не меняется.

Это экспериментальная реализация, ещё не проверенная на физическом 665.
Программа проверяет фактические architecture/skin, а не доверяет выбору в меню.
Для неизвестной архитектуры или микросхемы памяти чтение прекращается.
В случае ошибки можно отправить текст из журнала приложения; успешный дамп
создаётся только после полного чтения.

## Формат копии

JSON версии 1 (`format=harmony-hid-backup`) содержит исходный ответ GET_VERSION
в hex, firmware/board/flash/architecture/skin, время UTC, начальный адрес,
размер, SHA-256 и неизменённые байты конфигурации в Base64.
Это контейнер для исследования, не EZHex и не файл для записи на пульт.
SHA-256 служит для проверки передачи файла, а не заменяет контроль протокола.

## Транспорт

`HarmonyHidReader` реализует classic HID непосредственно в нашем проекте;
статически подключённая HIDAPI 0.14.0 предоставляет только системный USB-доступ.
Внешние Concordance/afterglow и их каталоги не требуются при сборке или запуске.
На Windows используется системный HID-драйвер, на macOS IOKit, на Linux hidraw
(для сборки нужен `libudev-dev`). Права на `/dev/hidraw*` даёт правило
`packaging/linux/usbnet/70-harmony-hid.rules` (046d:c110–c14f, тег `uaccess` —
доступ пользователю за компьютером). Его ставит «Настроить связь по USB…»
вместе с настройкой для 900, действует сразу, без переподключения.
Не следует заменять HID-драйвер через Zadig.

Источники описания протокола: GPL-3.0-or-later проект
[Concordance](https://github.com/jaymzh/concordance),
`libconcord/remote.cpp`, `remote_info.h`, `protocol.h`, `libhidapi.cpp`.
Авторы исходной реализации: Kevin Timmerman и Phil Dibowitz.
Соседние локальные проекты использованы только для чтения справочной информации.

Читатель использует GET_VERSION (0x10) и READ_FLASH (0x55). Для USB PID c121
системный канал сначала выполняет RESET_USB (0xe1, 0x01): инициализацию обмена,
не сброс устройства и не запись памяти. Архитектура 14:
config base 0x030000, cookie 0x4D505347, трёхбайтный end vector со смещения 4.
Для skin 66/69/71–75 разрешено чтение после проверки architecture=14.
Каждый блок ограничен 1022 байтами (700 для protocol 0), проверяются номера
пакетов, фактические длины, DONE, ёмкость flash и стабильность заголовка.
Ошибки и отмена не дают частичный файл под видом полной копии.

Следующий этап после получения реального дампа — разбор внутренней структуры,
сопоставление кнопок и преобразование проекта. Запись пока заблокирована.

## Harmony One

Для architecture=12 / skin=54 конфигурация читается с 0x040000.
Адрес configBase в JSON берётся из результата чтения, а не задаётся как 0x030000.
Пары architecture/skin проверяются совместно; skin One на architecture 14 отклоняется.
Это экспериментальное чтение исходных байтов GSPM; редактор этого формата ещё не реализован.
Чтение и запись готового EZHex доступны отдельно: «Пульт → Файлы конфигурации — все модели…».
Тесты с имитацией HID не подтверждают работу на физическом One.
