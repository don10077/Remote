## 2. Интерфейс: баги

- ✔ **Delete — оконный шорткат** (`mainWindow.cpp:411`): удаляет выбранное слева устройство/активность, даже когда фокус в таблице кнопок или команд; сами таблицы Delete не обрабатывают. Delete в таблице должен удалять строку, объект слева — Ctrl+Delete или шорткат с контекстом списка.
- Delete на активности PowerOff: пункт меню отключён, но шорткат работает — сначала вопрос «удалить?», потом ошибка ядра (`mainWindow.cpp:949-991`). Добавить проверку в начало `removeItem`.
- **Молчаливый отказ** «Прочитать/Записать/Сменить пульт» (`mainWindowRemote.cpp:94, 103, 240`: `if (busy()) return;`). Фоновая проверка подключения занимает сессию каждые 10 с на до 1,5 с — клик в это окно ничего не делает. Дождаться окончания проверки или сказать об этом.
- Esc/закрытие прогресса шлёт отмену и на стадиях без отмены (Restart — «не отключайте»), `mainWindowRemote.cpp:56, 86`. Фильтровать по стадии.
- `updateProblems` вызывает полную проверку конфигурации (с разбором ИК-сигналов) на каждую правку/отмену/выученную команду (`mainWindow.cpp:1641-1698`). Отложить таймером ~200 мс.
- `addFromDatabase` (`mainWindow.cpp:1252`) — тяжёлая работа в GUI-потоке только с WaitCursor.
- Резервная копия, прочитанная с пульта, открывается как рабочий документ из папки BackUp — Ctrl+S перезапишет копию (`mainWindowRemote.cpp:154-162`, средняя уверенность). Открывать без location.
- `getSaveFileName` без суффикса по умолчанию: на Linux файл сохранится без `.EZHex` (`mainWindow.cpp:865`, `mainWindowRemote.cpp:129, 368`); там же папка — `homePath()` вместо `lastDialogDir()`.
- Чтение журнала пульта — `std::thread(...).detach()` (`mainWindowRemote.cpp:385-401`): при выходе во время чтения обращение к разрушенному `qApp`; «Copy/Save» активны над заглушкой.
- «Recover IR data…» и «Set up USB connection…» есть только в меню шапки, не в строке меню «Пульт»; первый не отключается без документа.
- После смены пульта на 900 индикатор подключения неверен до 10 с — в `chooseRemote` не вызывается `probe()`.

## 3. Интерфейс: понятность

- Одно действие — разные слова: «Delete», «Remove», «Remove assignment of». Предлагаю: объекты — Delete, привязка кнопки — «Clear assignment».
- «Copy…» на вкладке кнопок копирует в другие активности, а Ctrl+C — в буфер. Назвать «Copy to activities…».
- В меню «Пульт» рядом «Check connection» и «Check configuration…» — переименовать первое в «Test connection».
- «Add device…» и «New device…» в Правке; «Choose configuration…» / «Open…» / «Open example». Предложение: «Recent configurations…», «Open example configuration».
- Два журнала: «Remote system log…» и «Journal…» → «Program journal…».
- «Ctrl+Z» зашит в строки и приклеен конкатенацией (`mainWindow.cpp:990, 1413, 1431, 1508…`, `mainWindowRemote.cpp:190`): на macOS это Cmd+Z, а переводчик не может переставить слова. Шаблон с `%1` и `QKeySequence(QKeySequence::Undo).toString(NativeText)`. Другая склейка: `mainWindowRemote.cpp:137`, `learnWizardDialog.cpp:100`, `mainWindow.cpp:798-800`.
- Undo/Redo в меню без названия действия — `undoStack_.undoText()` уже есть: «Undo “Rename X”».
- `confirmDiscard()` спрашивает «сохранить?» до выбора файла (`mainWindow.cpp:595, 626, 658`); если потом отменить выбор, вопрос был зря. Спрашивать после выбора (как уже сделано в `showStartDialog`).
- Ошибки связи: заголовок «Remote» и сырой текст. Писать операцию в заголовок («Write to remote failed») и дать кнопку «How to connect…».
- Enter на строке таблицы не открывает правку (только двойной щелчок, `configView.cpp:747`).
- Окна 1320×820 и диалоги ~720 по высоте не помещаются на 1080p при 150 % (1280×720 логических) — ограничивать по `availableGeometry`. `setFixedHeight(sizeHint())` в `commandDialog.cpp:99` обрежет длинный русский текст.
- Цвета мимо `theme.cpp`: `remotePanel.cpp:98-102, 455-462`, `toggleSwitch.cpp:100, 117` — проверить контраст в тёмной теме.
- `setMenuRole(QuitRole/AboutRole)` для Exit/About — на macOS роль по тексту в русском переводе не определится.

## 4. CLI

- `writeFile` (`main.cpp:179-183`) проверяет поток до flush/close — ошибка записи обязательной резервной копии может пройти незамеченной.
- `write` не запускает `check()` и не показывает diff (в GUI — запускает). Отказ при ошибках без `--force`.
- Если копию с пульта не удалось разобрать (`main.cpp:477`), запись идёт дальше без предупреждения и RF-настройки пульта теряются.
- Ctrl-C во время записи убивает процесс: `printProgress` всегда возвращает true. Обработчик SIGINT → флаг отмены.
- `shell`/`log`/`set` не принимают `--host`; `set` считает успехом пустой ответ без HTTP-статуса (`remoteServices.cpp:212-216`); `shell` при таймауте возвращает обрезанный вывод с кодом 0.
- `check` выходит с кодом 3, хотя в комментарии 0/1/2, в `--help` кодов нет; без аргументов — usage и код 0. `irdb show abc` → устройство 0 (`strtoull` без проверки). На Windows `irdb search`/`set`/`shell` теряют кириллицу (узкие `args[]`).
- README: в блоке команд нет `settings`, `set`, `log`, `shell`.
