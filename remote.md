## Использование / Usage

В меню **Пульт → Файлы конфигурации — все модели…** доступны чтение в файл и запись
готового файла. Можно выбрать модель или автоматическое определение. Фото и зоны
не требуются. Classic/Z-HID/MH обслуживаются встроенной libconcord; для USB-network
используется сетевой транспорт Harmony. Отдельная установка Concordance не нужна.

Перед записью проверяются формат, идентификатор модели и ограничения размера.
Для classic HID дополнительно проверяется карта flash; для One/GSPM — сигнатуры,
указатели и XOR16. Если чтение доступно, сначала сохраняется и проверяется новая
резервная копия. При ошибке чтения запись не продолжается. Для моделей без readback
нужно выбрать модель явно и подтвердить запись без копии. Аппаратные проверки новых
моделей не выполнялись; статус «Эксп.» нельзя считать гарантией успешной записи.

```text
harmony-cli models
harmony-cli transfer-info auto
harmony-cli transfer-read one One-backup.EZHex
harmony-cli transfer-write one One-config.EZHex --backup One-before.EZHex --yes
harmony-cli transfer-write 1000 Config.EZHex --without-backup --yes
```

Выходные файлы CLI и резервные копии не перезаписывают существующие файлы.
Для classic/Z используются EZHex с явными PROTOCOL/SKIN; для MH — ZIP с описанием
и одним файлом пользовательской конфигурации. Исследовательский `*.hid.json`
не является файлом для записи. Файлы прошивки и произвольные файлы памяти не принимаются.

## Ограничения моделей / Model limitations

- **1000/1000i:** запись готового пакета реализована; прошивка отказывает в чтении
  области конфигурации через исследованный транспорт (Afterglow `concord.py`).
- **Link, Link EMEA, Touch, Ultimate, Ultimate One, Ultimate Hub, Home Hub, 950:**
  встроенный MH-транспорт имеет путь обновления конфигурации, но для architecture 17
  upstream исключает чтение `/cfg/usercfg`. Принимается только поддержанный одиночный
  пакет userconfiguration; другие типы архивов не объявляются поддержанными.
- **800:** прототип architecture 18 / skin 86, MH. Поддержка экспериментальная;
  название не означает поддержку произвольного серийного устройства с похожим именем.
- **1100:** architecture 11, skins 62/63/64. Все три идентичности относятся к 1100.
- **1100i:** есть визуальный профиль, но отдельная достоверная аппаратная идентичность
  в исследованных исходниках не найдена. Чтение и запись отключены; skin не угадывается.
- **One:** architecture 12 / skin 54, GSPM с базы `0x040000`. Для 600/650/665/700
  используется architecture 14 и база `0x030000`. Варианты с суффиксом i перечислены
  отдельно по названиям ModelList. Файл другой модели отклоняется.

Config Update доказывает заявленную запись готового файла, а не успешное чтение каждой модели.

## Что добавлено / Implemented here

- Отдельный каталог физических моделей, не зависящий от визуальных профилей.
- Встроенная libconcord с classic HID, Z-HID и MH; чтение и запись готовых конфигураций
  через GUI и CLI, включая модели без фотографий и зон.
- Проверки контейнера, идентичности, карты памяти, резервной копии; запрет неоднозначного
  выбора при нескольких подключённых HID-пультах.
- Сетевое чтение 1100 и перенос готовых пакетов 1000/1000i/1100.
- Русские подписи нового окна; английские названия моделей и CLI.

## Что ещё не реализовано / Remaining work

Перенос готовых файлов не добавляет полноценные редакторы остальных форматов.
Для One остаётся перенос GSPM importer/builder из Afterglow/re-harmony; для 1100 —
Device Sequence и встроенные action lists; для 800 — GSGD и полная клавиатура.
Для остальных моделей нужны собственные адаптеры редактирования и проверки на
реальных конфигурациях. Наличие модели в libconcord не доказывает поддержку редактора.

## Проверки / Validation

В коде есть проверки контейнеров MH/EZHex, несовместимых моделей, границ GSPM,
контрольных сумм и параллельных сеансов. Аппаратные чтения и записи новых моделей
в рамках этой работы не выполнялись. После указания пользователя не собирать
сборка и исполняемые тесты не запускаются; заключительные правки проверяются
по исходникам и структуре файлов. Это не подтверждение прохождения полного тестового набора.
